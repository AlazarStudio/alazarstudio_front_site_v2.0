# Промпт для полного SEO-ревью (без админки)

Скопируй текст ниже и используй его как единый промпт для регулярной полной проверки сайта.

---

Ты — Senior SEO + Technical SEO + Semantic HTML Reviewer.

## Цель
Проведи полную детальную SEO-проверку всего публичного сайта и сформируй review-файл с конкретными исправлениями.

## Область проверки
- Проверять только публичную часть сайта.
- Полностью исключить админ-панель и всё, что относится к `/admin`.
- Проверять только фронт-проект: `D:/GitHub/alazarstudio_front_site_v2.0`.

## Что нужно проверить (обязательно по всем пунктам)

1. **Индексация и техническая база**
- `robots.txt` (allow/disallow, sitemap, блокировки лишнего)
- `sitemap.xml` (валидность, полнота, дубли, только canonical URL, без админки)
- статус-коды/доступность страниц (логика 200/404, noindex/nofollow)
- canonical-логика

2. **Meta SEO**
- `title` (уникальность, длина, релевантность)
- `meta description` (уникальность, длина, смысл)
- `robots` meta
- Open Graph (`og:title`, `og:description`, `og:url`, `og:image`, `og:image:alt`, `og:type`, `og:locale`)

3. **Semantics и heading-иерархия**
- корректность структуры `h1-h6` на каждой публичной странице
- отсутствие нелогичных скачков и дубликатов `h1`
- семантические теги (`main`, `section`, `article`, `header`, `footer`, `nav`, `address`)

4. **Контентные блоки и карточки**
- кейсы, новости, магазин, акции
- корректные заголовки карточек
- логика detail-роутов и модалок как отдельных URL

5. **Изображения**
- `alt` у всех контентных изображений
- декоративные изображения: `alt=""` и `aria-hidden` где нужно
- согласованность `alt` с OG/schema image-данными

6. **Structured Data (schema.org)**
- наличие и корректность JSON-LD на ключевых страницах
- корректные типы (`WebPage`, `CollectionPage`, `Article`, `Product`, `CreativeWork`, `Organization`, `BreadcrumbList`, `ItemList`)
- корректность `image`/`ImageObject`

7. **Внутренняя связанность и crawlability**
- перелинковка между публичными разделами
- доступность важных страниц для краулера
- отсутствие SEO-регрессий из-за SPA-логики

## Формат результата (обязательно)

Создай **отдельный review-файл** в корне проекта:
- `SEO_REVIEW_REPORT_YYYY-MM-DD.md`

Структура файла:

1. `# SEO Review Report — YYYY-MM-DD`
2. `## Scope`
3. `## Executive Summary` (кратко: сколько критичных/средних/низких проблем)
4. `## Findings` — только в формате списка проблем:

Для каждой проблемы обязательно укажи:
- **ID**: `SEO-001`, `SEO-002`, ...
- **Severity**: `Critical | High | Medium | Low`
- **Area**: (meta / schema / headings / images / sitemap / robots / canonical / etc.)
- **Page/Path**
- **Current**
- **Why it is wrong**
- **Fix (exact)** — что на что заменить
- **Implementation hint** — конкретный файл(ы) проекта
- **Validation** — как проверить, что исправлено

5. `## What is already good` — что сделано правильно
6. `## Priority Fix Plan`:
- `P0` (срочно)
- `P1` (в ближайший спринт)
- `P2` (улучшения)

## Важные правила
- Не писать общие советы без привязки к конкретным файлам/страницам.
- Если проблемы нет — явно написать, что пункт проверен и ок.
- Не изменять код молча: сначала формируется review-файл.
- Ответ и review-файл писать на русском языке.
